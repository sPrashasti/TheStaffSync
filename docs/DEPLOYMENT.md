# Deploying StaffSync

StaffSync runs as **one web service**: the Express API also serves the built React app, so the app and its API share one address. These steps use **Render** (free plan) and **MongoDB Atlas**. Any Node.js host works with the same build and start commands (see *Other hosts*).

Time needed: about 20 minutes the first time.

## What you need

- The GitHub repository (already at `github.com/sPrashasti/TheStaffSync`)
- A MongoDB Atlas cluster (the one used in development works)
- A free Render account: https://render.com (sign up with GitHub)
- Optional: an SMTP mailbox for "Forgot password" emails

## 1. Prepare MongoDB Atlas

1. **Use a separate database for production.** Copy your connection string and change the database name after `.mongodb.net/`, so production data never mixes with development and test data:

   ```
   mongodb+srv://<user>:<password>@cluster0.ehf3ymx.mongodb.net/staffsync?retryWrites=true&w=majority&appName=Cluster0
   ```

2. **Database Access:** use a database user with *Read and write to any database*. A dedicated production user with its own password is better than reusing the development one.
3. **Network Access:** Render's free plan has no fixed address, so add `0.0.0.0/0` (*Allow access from anywhere*). The database password is what protects it, so make it long and random.

## 2. Deploy on Render

1. In Render, choose **New → Blueprint**.
2. Connect the GitHub repository `TheStaffSync`. Render reads [render.yaml](../render.yaml) and proposes one web service called `staffsync`.
3. Render asks for the values marked secret:
   - **MONGO_URI**: the connection string from step 1 (database `staffsync`).
   - **SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, MAIL_FROM**: your email settings, or leave them blank for now (see step 5).
4. Click **Apply**. The first build takes a few minutes. It installs both apps, builds the React app, then starts the server.
5. When the service shows **Live**, note its address, e.g. `https://staffsync.onrender.com`.

Everything else is set by the blueprint:

- `NODE_ENV=production` and Node 24
- `TRUST_PROXY=1`, so rate limits see the real client address behind Render's proxy
- `TIMEZONE=Asia/Kolkata` and `WORKING_DAYS=Mon,Tue,Wed,Thu,Fri`
- a random `JWT_SECRET` generated by Render
- the health check on `/api/health`

The service's own address is used automatically for CORS and for password-reset links.

## 3. Create the first HR account

Production starts empty. Run the seed script **from your computer**, pointed at the production database. Use your own name, email and a strong password; these are not stored anywhere except the database.

**PowerShell** (Windows):

```powershell
cd server
$env:MONGO_URI = "mongodb+srv://<user>:<password>@cluster0.ehf3ymx.mongodb.net/staffsync?retryWrites=true&w=majority"
$env:SEED_HR_NAME = "Your Name"
$env:SEED_HR_EMAIL = "you@mts.example"
$env:SEED_HR_PASSWORD = "<a strong password>"
npm run seed
Remove-Item Env:MONGO_URI, Env:SEED_HR_PASSWORD
```

**macOS / Linux**:

```bash
cd server
MONGO_URI="mongodb+srv://…/staffsync?…" SEED_HR_NAME="Your Name" SEED_HR_EMAIL="you@mts.example" SEED_HR_PASSWORD="<a strong password>" npm run seed
```

Do **not** run `npm run seed:demo` against production: it creates demo accounts with a shared password.

## 4. Check it is working

1. Open `https://<your-service>.onrender.com/api/health`. You should see `"database": "connected"`.
2. Open `https://<your-service>.onrender.com` and log in with the HR account from step 3.
3. Add a manager and an employee under **Employees**, then walk through section A of [E2E-CHECKLIST.md](E2E-CHECKLIST.md).

## 5. Email for "Forgot password" (optional)

Without SMTP settings the app works normally, but "Forgot password" replies *"Password reset by email is not available. Contact HR."*

To turn it on, open Render → `staffsync` → **Environment** and set:

| Key | Microsoft 365 | Gmail |
|---|---|---|
| `SMTP_HOST` | `smtp.office365.com` | `smtp.gmail.com` |
| `SMTP_PORT` | `587` | `587` |
| `SMTP_USER` | a mailbox with *Authenticated SMTP* enabled | the Gmail address |
| `SMTP_PASS` | its password | an app password |
| `MAIL_FROM` | `StaffSync <that mailbox>` | `StaffSync <that address>` |

Saving restarts the service.

## Updating

Every push to `main` deploys automatically (`autoDeploy` in `render.yaml`). GitHub Actions runs lint, both test suites and the build on every push ([.github/workflows/ci.yml](../.github/workflows/ci.yml)); check it is green before relying on a release.

## Custom domain (optional)

1. Render → `staffsync` → **Settings → Custom Domains**, and follow the DNS steps there.
2. Set `APP_URL=https://hr.your-domain.com` in **Environment**, so reset links use the domain.
3. CORS accepts both the domain and the Render address automatically.

## Good to know

- **Free plan sleep:** the free plan stops the service after 15 minutes without visits; the next visit takes about a minute to wake it. A paid plan keeps it awake.
- **Logs:** Render → `staffsync` → **Logs** shows start-up messages and any server errors. Error responses to users never include internal details in production.
- **Indexes:** they are created automatically on start-up. After changing indexes in the code, run `npm run db:indexes` with `MONGO_URI` set to production, as in step 3, to also remove old ones.
- **Security headers:** pages are served with a strict Content-Security-Policy (scripts only from this site), the API with one that allows nothing, plus HSTS. Nothing to configure.
- **Rate limits** are kept in memory, so they reset when the service restarts. Running several instances would need a shared store.

## Other hosts

Any host that runs Node.js 24 can use the root scripts:

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Start command | `npm start` |
| Health check | `/api/health` |
| Environment | `NODE_ENV=production`, `MONGO_URI`, `JWT_SECRET` (32+ random characters), `CLIENT_URL` or `APP_URL` = the public address, `TRUST_PROXY=1` behind a load balancer |

To host the frontend separately (for example on a static host), build it with `VITE_API_URL=https://<api-address>/api`, set `SERVE_CLIENT=false` and `CLIENT_URL=<frontend address>` on the API, and serve `client/dist` with a fallback to `index.html` for unknown paths.
